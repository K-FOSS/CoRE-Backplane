# NATPuncher chart

NATPuncher deploys CoTURN as CoRE's STUN/TURN service for NAT traversal and
relayed connectivity. It is owned by `Apps/Network/NATPuncher.yaml`.

Review listening/public addresses, UDP/TCP/TLS ports, relay ranges,
firewall/NAT policy, authentication realm/users, secret references,
LoadBalancer exposure, DNS and certificates.

CoTURN uses REST/shared-secret authentication. The `natpuncher-turn-auth`
Secret is generated by External Secrets and injected into CoTURN at startup;
its value is not stored in Git or the ConfigMap. TURN clients must derive
time-limited credentials from that shared secret using the
[CoTURN REST API authentication format](https://github.com/coturn/coturn/blob/master/README.turnserver).

The Redis connection uses the site-local Dragonfly Service ClusterIP with the
public Dragonfly hostname supplied as TLS SNI. Update `dragonflyAddress` if the
Dragonfly Service is recreated and receives a new ClusterIP.

The generated `natpuncher-turn-auth` Secret is published to CoreVault through
the [External Secrets Operator PushSecret resource](https://external-secrets.io/latest/api/pushsecret/)
at `Network/NATPuncher/<region>/<datacenter>/<cluster>/TurnAuth`, under the
`Secret` property. Consumers on another cluster should read that path through
an ExternalSecret; do not copy the Kubernetes Secret or put its value in Git.

Validate STUN discovery and authenticated TURN allocations from outside the
cluster. Test UDP and TCP/TLS fallback separately and monitor allocation
failures, bandwidth, port exhaustion and authentication errors.

TURN is abuse-sensitive. Do not enable anonymous relay, expose management
interfaces, or use weak static credentials.
